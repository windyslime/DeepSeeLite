# DeepSee 全应用审计 Team Run

## 目标与范围

对核心库、FastAPI 网关和相邻 `DeepSee-Desktop/frontend` 做只读完整审计，要求结论包含代码/命令证据、风险、最小修复和发布建议。父任务等待全部检查完成后统一复核与去重。

## 角色

- Security/Core Reviewer：检查网关、协议、配置、图片安全、流式资源与成本边界；继承当前会话模型与推理配置。
- Frontend/Integration Reviewer：检查 Desktop 真实接入、交互、可访问性、构建与跨仓库契约；继承当前会话模型与推理配置。
- Parent Reviewer：运行完整测试、构建、真实 HTTP/浏览器探针，复现高风险发现并汇总。

没有发生模型回退。子任务只读，没有编辑应用文件。

## 结果摘要

Security/Core Reviewer 确认：当前推理路由没有入站鉴权或并发/速率限制；协议丢弃完整消息历史；畸形 SSE 可抛裸异常；配置错误成为 500；`stream` 类型和上游 URL 校验不足。证据集中在 `deepsee_server/app.py`、`deepsee_server/protocols/*.py`、`deepsee/composer/deepseek.py` 和 `deepsee/config/loader.py`。

Frontend/Integration Reviewer 确认：Desktop 依赖的 `/health`、`/admin/traces`、CORS 和 `--web-dist` 不在当前核心主线；视觉模式、完整历史和 tool-call 契约不能成立；提前断流被标记成功；设置刷新、会话导航、焦点管理、图片大小检查和 key 存储仍需修复。证据集中在 `frontend/src/bridge/HttpDesktopBridge.ts`、`frontend/src/features/` 与 `docs/FRONTEND-DEVELOPMENT.md`。

Parent Reviewer 复核 Git 图后确认根因：安全网关实现提交 `ff80bdd` 与当前 `main` 的文档提交 `0f00733` 都从 `d3a0527` 分叉，`ff80bdd` 从未进入当前主线。真实探针得到 `/health` 404、`/admin/traces` 404、CORS OPTIONS 405、无配置 `/v1/models` 500；畸形 SSE 复现裸 `IndexError`，错误 TOML section 复现裸 `AttributeError`。

## 验证证据

- 核心：`uv run pytest -q`，269 passed；`uv build` 成功。
- Desktop：`pnpm test -- --run`，17 passed；`pnpm lint` 与 `pnpm build` 成功。
- 浏览器：本地首屏和 API 页面可渲染、无 1280x720 横向溢出，但显示网关连接失败。
- 两仓库 `git diff --check` 通过。
- `pnpm audit --prod` 因 npmmirror 无 audit endpoint 未完成。

## 风险与决策

当前发布决策为 No-go。第一批修复必须把 `ff80bdd` 的安全网关集成正确合入当前主线并恢复其测试，再增加真实跨仓库 E2E；随后处理错误语义、资源边界和 Desktop 工作流/可访问性。完整清单见 `.ohmycodex/plans/review.md`。
